# Component library

The shared UI components, where each is used, and the state vocabulary they
share. The block below is generated by `core.frontend.component_audit`; do not
edit it by hand.

Rules a component must satisfy:

* **Presentation only.** A component renders what it is given. It does not read
  the database, does not decide access, and does not name a product interface.
  Those belong to the route and the template that call it.
* The state vocabulary is shared. A status reads the same in a server template
  and in a client script, because both use the same badge classes.
* Adoption is counted from the pages that use the component, not from a number
  written into this document. A page that is **not yet** migrated keeps its
  hand-rolled markup and is listed as such rather than implied to be covered.

This is **not a redesign**. The components exist to stop the same table, badge
and empty state being written again on every page; they do not change what any
page does.

### CSS ownership of the classes components render

Every class a component renders has exactly one owner. **OWNED** means an SYLTHARAE stylesheet defines it, or the component declares it in its own `classes:` header. **THIRD_PARTY** means a bundled dependency defines it - Bootstrap and Bootstrap Icons are expected dependencies, and using them is not a finding. **UNKNOWN** means nobody does, and an unknown class is how a component invents a style: it fails the guardrail test rather than being reported and forgotten.
